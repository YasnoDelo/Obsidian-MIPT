# Двухузловая СМО с MAP-входом и общей конечной орбитой: построение марковской цепи и вывод характеристик

## 1. Что моделируем

Есть два последовательно соединённых одноканальных узла и общая орбита для повторных обращений.

1. Внешняя заявка пытается войти в узел 1. Если он заполнен, заявка переходит в орбиту; если орбита тоже заполнена, заявка окончательно теряется.
2. Закончив обслуживание в узле 1, заявка пытается войти в узел 2. Если узел 2 заполнен, заявка направляется в орбиту; если орбита заполнена, заявка окончательно теряется.
3. Из орбиты заявка вновь пытается поступить **только в узел 1** и, попав в него, заново проходит обе фазы обслуживания. При занятом узле 1 попытка неудачна, но заявка остаётся в орбите.
4. Узлы имеют по одному прибору, дисциплину FIFO. Обслуживание экспоненциальное, с интенсивностями $\mu_1$ и $\mu_2$. Каждая заявка орбиты независимо повторяет попытки через экспоненциальные интервалы интенсивности $\nu$.

Обозначим $K_1,K_2$ **полные вместимости** узлов (включая обслуживаемую заявку), $R$ — вместимость орбиты. Внешний поток задают матрицы MAP $D_0,D_1\in\mathbb R^{m\times m}$.

**Задача:** найти вероятность окончательной потери внешней заявки $P_{\mathrm{loss}}$, среднее время успешной заявки от её первого поступления до выхода из узла 2, а также характеристики выходов узла 1.

## 2. Почему выбран именно такой марковский процесс

Пусть

$$
\boxed{X(t)=(J(t),N_1(t),N_2(t),O(t)).}
$$

$J(t)\in\{1,\ldots,m\}$ — текущая фаза MAP; $N_1(t)$ и $N_2(t)$ — полные численности на узлах; $O(t)$ — число заявок в орбите.

**Почему этих четырёх компонент достаточно?** При экспоненциальных временах обслуживания и попыток распределение времени до очередного события не зависит от уже прошедшего времени. Фаза MAP определяет закон следующих внешних поступлений. Поэтому вероятности будущих состояний определяются только $X(t)$: процесс является непрерывновременной марковской цепью (CTMC).

Отдельное состояние обозначим $x=(v,a,b,r)$, где

$$
1\le v\le m,\quad 0\le a\le K_1,\quad 0\le b\le K_2,\quad 0\le r\le R.
$$

Пространство состояний и его мощность:

$$
\mathcal S=\{(v,a,b,r)\},\qquad
\boxed{|\mathcal S|=m(K_1+1)(K_2+1)(R+1).}
$$

> **Состояние — не траектория отдельной заявки.** В нём содержатся только численности. Поэтому для вероятности потерь и потоков его хватает, а для задержки *только успешно завершённых* заявок потребуется дополнительная цепь с помеченной заявкой.

## 3. Что такое $D_0$ и $D_1$

При фазе $v$ управляющей цепи:

- $(D_0)_{vw}\ge0$ при $v\ne w$ — интенсивность смены фазы $v\to w$ **без** внешнего поступления;
- $(D_1)_{vw}\ge0$ при любых $v,w$ — интенсивность **поступления одной заявки** со сменой фазы $v\to w$ (в том числе при $v=w$);
- диагональ $D_0$ отрицательна и учитывает обе группы событий.

Генератор фаз MAP и стационарная интенсивность входа:

$$
D=D_0+D_1,\qquad D\mathbf e_m=\mathbf0,
$$

$$
\boldsymbol\theta D=\mathbf0,\qquad
\boldsymbol\theta\mathbf e_m=1,\qquad
\boxed{\lambda=\boldsymbol\theta D_1\mathbf e_m.}
$$

Здесь $\lambda$ считает **только внешние поступления**: повторные входы из орбиты не являются новыми внешними заявками.

## 4. Как из событий получаются строки матрицы $Q$

Генератор $Q=(q_{xy})$ задаётся соотношениями

$$
q_{xy}=\lim_{h\downarrow0}\frac{\Pr\{X(t+h)=y\mid X(t)=x\}}{h},\quad x\ne y,
$$

$$
\boxed{q_{xx}=-\sum_{y\ne x}q_{xy}.}
$$

**Алгоритм построения одной строки $Q$:** фиксируем состояние $x$; перечисляем все события, которые реально меняют состояние; в столбец соответствующего нового состояния вписываем интенсивность события; на диагонали ставим минус сумму внедиагональных интенсивностей. Если несколько событий приводят к одному новому состоянию, их интенсивности складываются.

Обозначим $z=(a,b,r)$ и введём четыре правила изменения численностей.

### 4.1. Внешнее поступление

$$
f(z)=\begin{cases}
(a+1,b,r),&a<K_1,\\
(a,b,r+1),&a=K_1,\ r<R,\\
(a,b,r),&a=K_1,\ r=R.
\end{cases}
$$

Событие $ (v,z)\to(w,f(z))$ имеет интенсивность $(D_1)_{vw}$. В третьем случае заявка потеряна. Если $v=w$, событие не меняет состояние $X(t)$; его **не добавляют как отдельный скачок**, но учитывают в интенсивности потерь.

### 4.2. Завершение обслуживания в узле 1

При $a>0$ с интенсивностью $\mu_1$ происходит переход $(v,z)\to(v,g_1(z))$, где

$$
g_1(z)=\begin{cases}
(a-1,b+1,r),&b<K_2,\\
(a-1,b,r+1),&b=K_2,\ r<R,\\
(a-1,b,r),&b=K_2,\ r=R.
\end{cases}
$$

В последнем случае заявка теряется после обслуживания на узле 1, но численность $a$ уменьшается; значит, состояние действительно меняется.

### 4.3. Завершение обслуживания в узле 2

При $b>0$ с интенсивностью $\mu_2$:

$$
(v,a,b,r)\longrightarrow(v,a,b-1,r).
$$

Это **успешный выход из всей системы**.

### 4.4. Повторная попытка из орбиты

При $r>0$ суммарная интенсивность попыток равна $r\nu$, поскольку минимум $r$ независимых $\operatorname{Exp}(\nu)$-интервалов имеет распределение $\operatorname{Exp}(r\nu)$.

Если $a<K_1$, происходит переход

$$
(v,a,b,r)\xrightarrow{\ r\nu\ }(v,a+1,b,r-1).
$$

Если $a=K_1$, попытка неудачна, заявка остаётся в орбите, а состояние не меняется: в генераторе такой скачок отсутствует.

**Все переходы:**

| Событие | Условие | Новое состояние | Интенсивность |
|---|---|---|---|
| Смена фазы без заявки | $w\ne v$ | $(w,a,b,r)$ | $(D_0)_{vw}$ |
| Внешнее поступление | Всегда | $(w,f(z))$ | $(D_1)_{vw}$ |
| Завершение узла 1 | $a>0$ | $(v,g_1(z))$ | $\mu_1$ |
| Завершение узла 2 | $b>0$ | $(v,a,b-1,r)$ | $\mu_2$ |
| Успешная попытка из орбиты | $r>0,\ a<K_1$ | $(v,a+1,b,r-1)$ | $r\nu$ |

## 5. Непосредственное построение одной строки $Q$

Возьмём **символьный минимальный случай** $K_1=K_2=R=1$, сохраняя произвольные $m,D_0,D_1,\mu_1,\mu_2,\nu$. Пусть численности равны $(a,b,r)=(1,1,0)$, а фаза MAP равна $v$.

- Внешний приход не может войти в заполненный узел 1, поэтому перемещается в свободную орбиту: $(v,1,1,0)\to(w,1,1,1)$ с интенсивностью $(D_1)_{vw}$.
- Завершение в узле 1 при заполненном узле 2 направляет заявку в орбиту: $(v,1,1,0)\to(v,0,1,1)$ с интенсивностью $\mu_1$.
- Завершение в узле 2: $(v,1,1,0)\to(v,1,0,0)$ с интенсивностью $\mu_2$.
- Смена фазы без заявки: $(v,1,1,0)\to(w,1,1,0)$ с интенсивностью $(D_0)_{vw}$ при $w\ne v$.

Именно эти переходы формируют одну блочную строку ниже. **Здесь ещё не решаются уравнения — мы только записываем все физически возможные события.**

## 6. Явный вид матрицы $Q$

### 6.1. Полностью выписанная блочная матрица для $K_1=K_2=R=1$

Упорядочим состояния сначала по $(a,b,r)$, а внутри каждого такого состояния — по фазе $v=1,\ldots,m$:

$$
\begin{array}{llll}
z_1=(0,0,0),&z_2=(0,0,1),&z_3=(0,1,0),&z_4=(0,1,1),\\
z_5=(1,0,0),&z_6=(1,0,1),&z_7=(1,1,0),&z_8=(1,1,1).
\end{array}
$$

Каждый элемент следующей матрицы — блок размера $m\times m$. Обозначим $I=I_m$, $L_1=\mu_1I$, $L_2=\mu_2I$, $V=\nu I$; символ $0$ — нулевой блок.

$$
\boxed{
Q_{\,K_1=K_2=R=1}=
\begin{pmatrix}
D_0&0&0&0&D_1&0&0&0\\
0&D_0-V&0&0&V&D_1&0&0\\
L_2&0&D_0-L_2&0&0&0&D_1&0\\
0&L_2&0&D_0-L_2-V&0&0&V&D_1\\
0&0&L_1&0&D_0-L_1&D_1&0&0\\
0&0&0&L_1&0&D_0+D_1-L_1&0&0\\
0&0&0&L_1&L_2&0&D_0-L_1-L_2&D_1\\
0&0&0&L_1&0&L_2&0&D_0+D_1-L_1-L_2
\end{pmatrix}.
}
$$

**Как читать матрицу:** блок строки $7$, столбца $4$ равен $L_1=\mu_1I$ — окончание обслуживания на узле 1, после которого заявка из-за занятости узла 2 поступает в орбиту: $z_7=(1,1,0)\to z_4=(0,1,1)$. Блок $(7,5)$ равен $L_2=\mu_2I$ — окончание обслуживания узла 2: $z_7\to z_5=(1,0,0)$. Блок $(7,8)$ равен $D_1$ — внешний приход в орбиту: $z_7\to z_8=(1,1,1)$.

Блоки $(6,6)$ и $(8,8)$ содержат **$D_0+D_1$**, потому что в этих состояниях первый узел и орбита заполнены: внешний приход может изменить фазу MAP, но не меняет численностей. В частности, при сохранении фазы такой приход вообще не создаёт скачка марковской цепи.

### 6.2. Общая матрица для любых $K_1,K_2,R,m$

Теперь пусть вместимости произвольны. Обозначим

$$
\mathcal Z=\{0,\ldots,K_1\}\times\{0,\ldots,K_2\}\times\{0,\ldots,R\},\qquad N=|\mathcal Z|.
$$

Определим матрицу внешних поступлений $P_A\in\mathbb R^{N\times N}$:

$$
(P_A)_{zz'}=\mathbf1_{\{z'=f(z)\}}.
$$

Она содержит в каждой строке ровно одну единицу. Если система не может принять внешнюю заявку ни на узел 1, ни в орбиту, эта единица стоит на диагонали.

Определим генератор $B\in\mathbb R^{N\times N}$ для обслуживания и успешных повторных попыток без смены фазы MAP:

$$
\begin{aligned}
B_{zz'}={}&\mu_1\mathbf1_{\{a>0\}}\big(\mathbf1_{\{z'=g_1(z)\}}-\mathbf1_{\{z'=z\}}\big)\\
&+\mu_2\mathbf1_{\{b>0\}}\big(\mathbf1_{\{z'=(a,b-1,r)\}}-\mathbf1_{\{z'=z\}}\big)\\
&+r\nu\mathbf1_{\{a<K_1,\,r>0\}}\big(\mathbf1_{\{z'=(a+1,b,r-1)\}}-\mathbf1_{\{z'=z\}}\big).
\end{aligned}
$$

Здесь все слагаемые, условия которых не выполняются, полагаются нулевыми. $B\mathbf e_N=\mathbf0$, $P_A\mathbf e_N=\mathbf e_N$.

**При порядке состояний «сначала $(a,b,r)$, затем фаза MAP»** блоки генератора $Q$ имеют явный вид:

$$
\boxed{Q_{zz'}=\mathbf1_{\{z=z'\}}D_0+(P_A)_{zz'}D_1+B_{zz'}I_m,\qquad z,z'\in\mathcal Z.}
$$

Следовательно,

$$
\boxed{Q=I_N\otimes D_0+P_A\otimes D_1+B\otimes I_m.}
$$

Если упорядочивать **сначала фазу MAP, затем численности**, эквивалентная матрица получается перестановкой строк и столбцов:

$$
\boxed{Q=D_0\otimes I_N+D_1\otimes P_A+I_m\otimes B.}
$$

Это **один и тот же марковский процесс** в разных порядках нумерации состояний.

Контроль: для любого порядка нумерации

$$
q_{xy}\ge0\quad(x\ne y),\qquad\boxed{Q\mathbf e=\mathbf0}.
$$

## 7. Как из $Q$ получаются вероятности

Пусть $\boldsymbol\pi=(\pi(v,a,b,r))$ — стационарное распределение, то есть вероятность нахождения в каждом состоянии в произвольный момент времени. Оно находится из линейной системы

$$
\boxed{\boldsymbol\pi Q=\mathbf0,\qquad\boldsymbol\pi\mathbf e=1.}
$$

Это уравнение **баланса потоков вероятности**: в стационарном режиме интенсивность входа в каждое состояние равна интенсивности выхода из него.

Сразу после нахождения $\boldsymbol\pi$ можно вычислить:

$$
P(N_1=K_1)=\sum_{v,b,r}\pi(v,K_1,b,r),\qquad
P(O=R)=\sum_{v,a,b}\pi(v,a,b,R),
$$

$$
\boxed{L=\sum_{v,a,b,r}(a+b+r)\pi(v,a,b,r)},
$$

где $L$ — среднее число заявок во всей системе (на обоих узлах и в орбите).

## 8. Как из $\boldsymbol\pi$ получается вероятность окончательной потери

У заявки имеются ровно два возможных места **окончательной** потери.

**Потеря при внешнем поступлении:** $a=K_1$ и $r=R$. При фазе $v$ интенсивность поступлений равна $d_v=(D_1\mathbf e_m)_v$, поэтому

$$
\boxed{\lambda_{\mathrm{loss},0}=
\sum_{v=1}^{m}\sum_{b=0}^{K_2}\pi(v,K_1,b,R)d_v.}
$$

**Потеря после первого узла:** $a>0$, $b=K_2$, $r=R$. Поэтому

$$
\boxed{\lambda_{\mathrm{loss},12}=
\mu_1\sum_{v=1}^{m}\sum_{a=1}^{K_1}\pi(v,a,K_2,R).}
$$

**Успешный окончательный выход:** завершение обслуживания узла 2:

$$
\boxed{\lambda_{\mathrm{out},2}=\mu_2\sum_{v,a,r}\sum_{b=1}^{K_2}\pi(v,a,b,r).}
$$

Средний поток внешних заявок в стационарном режиме распадается на успешные окончательные выходы и безвозвратные потери:

$$
\lambda=\lambda_{\mathrm{out},2}+\lambda_{\mathrm{loss},0}+\lambda_{\mathrm{loss},12}.
$$

Деление на $\lambda$ даёт **вероятность окончательной потери типичной внешней заявки**:

$$
\boxed{
P_{\mathrm{loss}}=\frac{\lambda_{\mathrm{loss},0}+\lambda_{\mathrm{loss},12}}{\lambda}
=1-\frac{\lambda_{\mathrm{out},2}}{\lambda}.}
$$

При MAP внешние поступления чаще происходят в одних фазах и реже в других. Поэтому, вообще говоря, доля **потерянных внешних заявок** не равна доле **времени**, когда первый узел и орбита заполнены.

## 9. Как из процесса получить межконцевую задержку

Межконцевая задержка — время между **первым внешним поступлением** заявки и её окончательным выходом из узла 2. Повторные обслуживания и пребывание в орбите включаются.

### 9.1. Время до любого исхода

Если в $T_{\mathrm{all}}$ учитываются **все** внешние заявки, включая потерянные (мгновенная потеря даёт нулевое время), по формуле Литтла:

$$
\boxed{\mathbb E[T_{\mathrm{all}}]=\frac{L}{\lambda}.}
$$

Но это **не** задержка только успешно завершённых заявок, поскольку часть заявок теряется после длительного пребывания в системе.

### 9.2. Задержка успешно обслуженной заявки: зачем нужна помеченная цепь

#### 9.2.1. Почему недостаточно исходного процесса $X(t)$

Состояние исходной цепи $X(t)=(J(t),N_1(t),N_2(t),O(t))$ содержит только **число** заявок на узлах и в орбите. Например, $X(t)=(1,2,1,1)$ не говорит, на каком узле находится конкретная заявка А и сколько заявок стоят в очереди перед ней. Поэтому по цепи $X(t)$ нельзя непосредственно установить, сколько времени А проведёт в системе и чем закончится её путь.

Формула Литтла $L/\lambda$ даёт среднее время до **любого окончательного исхода** (успеха или потери), а нам требуется $\mathbb E[T\mid S]$, где $S$ — событие успешного завершения на втором узле. Это разные показатели. Если одна заявка успешно вышла через 10 единиц времени, а другая потерялась через 2, среднее время до исхода равно 6, а среднее время *успешной* заявки равно 10.

#### 9.2.2. Расширенное состояние

Выделим («пометим») одну **внешнюю** заявку А при её первом поступлении. Остальные заявки продолжают двигаться по обычным правилам. Введём цепь

$$
\boxed{Y(t)=(J(t),N_1(t),N_2(t),O(t),H(t),P(t)).}
$$

Здесь $H(t)\in\{1,2,O\}$ — местонахождение А (первый узел, второй узел или орбита), а $P(t)$ — позиция А в очереди FIFO на выбранном узле: $P=1$ означает обслуживание, $P=2$ — одну заявку перед А. Для $H=O$ позиция не нужна: повторные попытки всех орбитальных заявок независимы и имеют одинаковую интенсивность $\nu$.

Пример: $Y(t)=(1,2,1,1,1,2)$ означает, что MAP в фазе 1, на первом узле две заявки, на втором одна, в орбите одна, **А стоит второй на первом узле**. Когда обслуживаемая перед А заявка завершит первую фазу, позиция А изменится $P:2\to1$.

В переходах новой цепи нужно различать события с А и события с остальными заявками:

- Если А стоит на узле 1 или 2 на позиции $P>1$, завершение обслуживания стоящей перед ней заявки уменьшает её позицию на единицу.
- Если А обслуживается на узле 1 ($H=1,P=1$), после завершения она переходит в конец очереди узла 2 (при наличии места), в орбиту (если узел 2 полон, но орбита не полна) или теряется (если оба заполнены).
- Если А обслуживается на узле 2 ($H=2,P=1$), завершение её обслуживания означает успешный выход.
- Если А находится в орбите среди $r$ заявок, **её собственная** попытка происходит с интенсивностью $\nu$, а попытки остальных $r-1$ заявок — с суммарной интенсивностью $(r-1)\nu$. При свободном месте в узле 1 А поступает в конец его очереди; при полном узле остаётся в орбите.

При этом численности $N_1,N_2,O$ по-прежнему **включают помеченную заявку**. Новые переменные $H,P$ не добавляют в систему физическую заявку, а только указывают, какая из уже учтённых заявок выделена.

#### 9.2.3. Поглощение и матрица генератора

Наблюдение за А заканчивается одним из двух исходов:

- **SUCCESS:** А завершила обслуживание на узле 2;
- **LOSS:** А безвозвратно потерялась после обслуживания на узле 1.

Эти состояния называются *поглощающими*: после достижения исхода путь выделенной заявки закончен. Если А мгновенно теряется **при первоначальном внешнем поступлении**, она не попадает в переходные состояния помеченной цепи; этот исход учитывается в её начальном распределении.

При упорядочении сначала всех непоглощающих состояний, а затем SUCCESS и LOSS генератор имеет блочную структуру

$$
\boxed{
Q_{\mathrm{tag}}=
\begin{pmatrix}
A&\mathbf g&\boldsymbol\ell\\
\mathbf0&0&0\\
\mathbf0&0&0
\end{pmatrix},\qquad
A\mathbf e+\mathbf g+\boldsymbol\ell=\mathbf0.
}
$$

Смысл блоков:

| Обозначение | Что задаёт |
|---|---|
| $A$ | Интенсивности переходов между состояниями, в которых А ещё находится в системе; диагональ учитывает также уход в SUCCESS и LOSS |
| $g_x$ | Интенсивность успешного выхода А из переходного состояния $x$ |
| $\ell_x$ | Интенсивность окончательной потери А из переходного состояния $x$ |

В частности,

$$
g_x=\begin{cases}\mu_2,&H=2,\ P=1,\\0,&\text{иначе},\end{cases}
\qquad
\ell_x=\begin{cases}\mu_1,&H=1,\ P=1,\ N_2=K_2,\ O=R,\\0,&\text{иначе}.\end{cases}
$$

Сумма интенсивностей каждого ряда полного генератора равна нулю. Поэтому в переходных строках $A\mathbf e+\mathbf g+\boldsymbol\ell=\mathbf0$.

#### 9.2.4. Начальное распределение $\boldsymbol\gamma$

Чтобы усреднить результаты по *типичной внешней заявке*, необходимо определить, в каком состоянии А оказывается **сразу после первого поступления**. Обозначим распределение по переходным состояниям помеченной цепи через строку $\boldsymbol\gamma$.

Внешнее поступление происходит из исходного состояния $(v,a,b,r)$ одновременно с переходом MAP в фазу $w$ с интенсивностью $(D_1)_{vw}$. Вес этого варианта на одну внешнюю заявку равен

$$
\boxed{\frac{\pi(v,a,b,r)(D_1)_{vw}}{\lambda}.}
$$

Поступившая А размещается:

1. В конце очереди узла 1 с позицией $P=a+1$, если $a<K_1$.
2. В орбите, если $a=K_1$ и $r<R$.
3. Не размещается нигде и сразу теряется, если $a=K_1$ и $r=R$.

В первых двух случаях вес добавляется к соответствующему компоненту $\boldsymbol\gamma$ (если разные события приводят к одному состоянию, их веса складываются). В третьем — не добавляется. Поэтому $\boldsymbol\gamma$ является **субвероятностным** вектором:

$$
\boxed{\boldsymbol\gamma\mathbf e=1-\frac{\lambda_{\mathrm{loss},0}}{\lambda}.}
$$

В отличие от произвольного момента времени, распределение состояний при внешнем поступлении взвешено интенсивностями $D_1$; при MAP нельзя просто заменить его на $\boldsymbol\pi$.

#### 9.2.5. Уравнение для вероятности успешного завершения

Для каждого переходного состояния $x$ обозначим

$$
\boxed{h_x=\Pr_x\{S\}},
$$

где $S$ — событие, что А в конечном итоге выйдет через второй узел. Если А уже в SUCCESS, вероятность успеха равна единице; если в LOSS — нулю.

За малый интервал $dt$, начиная из переходного состояния $x$, процесс может остаться в $x$, перейти в другое переходное состояние $y$, успешно поглотиться или потеряться. По формуле полной вероятности

$$
h_x=(1+A_{xx}dt)h_x
+\sum_{y\ne x}A_{xy}dt\,h_y
+g_xdt+o(dt).
$$

После переноса слагаемых, деления на $dt$ и перехода к пределу получаем

$$
-\sum_y A_{xy}h_y=g_x.
$$

Собирая эти равенства по всем $x$, получаем **первую линейную систему**:

$$
\boxed{(-A)\mathbf h=\mathbf g.}
$$

Вероятность успеха типичной внешней заявки равна

$$
\boxed{P(S)=\boldsymbol\gamma\mathbf h.}
$$

#### 9.2.6. Уравнение для времени, учитывающего только успешные исходы

Обозначим $T$ время от первого внешнего поступления до окончательного исхода, а $\mathbf1_S$ индикатор успешного исхода. Для каждого переходного состояния введём

$$
\boxed{u_x=\mathbb E_x[T\mathbf1_S].}
$$

Если А обслужена успешно за время $T$, в величину входит $T$; если А потеряна, вклад равен нулю. Это **не** то же самое, что $\mathbb E_x[T]$.

Разобьём ожидание на первый короткий промежуток $dt$ и оставшееся время. Малый промежуток $dt$ учитывается лишь в тех траекториях, которые завершатся успехом, поэтому его средний вклад — $h_xdt$. Оставшаяся часть вычисляется по переходным состояниям:

$$
u_x=h_xdt+(1+A_{xx}dt)u_x
+\sum_{y\ne x}A_{xy}dt\,u_y+o(dt).
$$

Перенос, деление на $dt$ и предельный переход дают

$$
-\sum_yA_{xy}u_y=h_x.
$$

То есть **вторую линейную систему**:

$$
\boxed{(-A)\mathbf u=\mathbf h.}
$$

Она означает: сначала рассчитываем шансы успеха из каждого состояния $\mathbf h$, затем по ним — среднее время, взвешенное по успешным исходам, $\mathbf u$.

#### 9.2.7. Формула межконцевой задержки

По определению условного математического ожидания

$$
\mathbb E[T\mid S]=\frac{\mathbb E[T\mathbf1_S]}{\Pr(S)}.
$$

С учётом начального распределения

$$
\mathbb E[T\mathbf1_S]=\boldsymbol\gamma\mathbf u,
\qquad
\Pr(S)=\boldsymbol\gamma\mathbf h.
$$

Отсюда

$$
\boxed{\mathbb E[T\mid S]=\frac{\boldsymbol\gamma\mathbf u}{\boldsymbol\gamma\mathbf h}.}
$$

Если матрица $-A$ обратима (помеченная заявка почти наверное достигает одного из исходов), то $\mathbf h=(-A)^{-1}\mathbf g$, $\mathbf u=(-A)^{-2}\mathbf g$. Получаем эквивалентную матричную формулу:

$$
\boxed{\mathbb E[T\mid S]=
\frac{\boldsymbol\gamma(-A)^{-2}\mathbf g}
{\boldsymbol\gamma(-A)^{-1}\mathbf g}.}
$$

**Проверки правильности модели:**

$$
\boxed{
\boldsymbol\gamma\mathbf h=\frac{\lambda_{\mathrm{out},2}}{\lambda},
\qquad
\boldsymbol\gamma(-A)^{-1}\mathbf e=\frac{L}{\lambda}.
}
$$

Первое равенство сопоставляет вероятность успешного исхода с отношением интенсивностей потоков. Второе сопоставляет среднее время до любого исхода с формулой Литтла. Замена $\mathbb E[T\mid S]$ на $L/\lambda_{\mathrm{out},2}$ была бы ошибкой: в $L$ учитываются также заявки, которые позже потеряются.

#### 9.2.8. Иллюстрация решения двух систем на двух состояниях

Для понимания метода временно рассмотрим вспомогательную поглощающую цепь, не являющуюся полной СМО с орбитой:

- Из состояния 1 с интенсивностью $1$ происходит переход в состояние 2 и с интенсивностью $1$ — потеря.
- Из состояния 2 с интенсивностью $2$ происходит успешный выход.
- Начальное состояние всегда 1.

Тогда

$$
A=\begin{pmatrix}-2&1\\0&-2\end{pmatrix},\qquad
\mathbf g=\begin{pmatrix}0\\2\end{pmatrix},\qquad
\boldsymbol\ell=\begin{pmatrix}1\\0\end{pmatrix},\qquad
\boldsymbol\gamma=(1,0).
$$

Из $(-A)\mathbf h=\mathbf g$:

$$
\begin{cases}2h_1-h_2=0,\\2h_2=2,\end{cases}
\qquad
\boxed{\mathbf h=\begin{pmatrix}0.5\\1\end{pmatrix}.}
$$

То есть успех из состояния 1 имеет вероятность $0.5$, из состояния 2 — вероятность $1$.

Из $(-A)\mathbf u=\mathbf h$:

$$
\begin{cases}2u_1-u_2=0.5,\\2u_2=1,\end{cases}
\qquad
\boxed{\mathbf u=\begin{pmatrix}0.5\\0.5\end{pmatrix}.}
$$

Поэтому

$$
\boxed{\Pr(S)=0.5,\qquad
\mathbb E[T\mid S]=\frac{0.5}{0.5}=1.}
$$

Проверка без матриц: при условии успеха сначала ожидаем в состоянии 1 в среднем $1/(1+1)=0.5$ единицы времени, затем в состоянии 2 — $1/2=0.5$. Их сумма равна $1$.

**Для исходной модели** меняются только размеры $A$, $\mathbf h$, $\mathbf u$ и правило составления $\boldsymbol\gamma$; обе линейные системы и формула задержки остаются такими же. Полный численный пример для СМО приведён в разделе 11.

## 10. Что можно сказать о выходном потоке узла 1

Назовём **выходом первого узла** каждое завершение его обслуживания, включая передачу в орбиту и потерю (при другой постановке можно учитывать только успешные передачи на узел 2).

Пусть $H_1$ — матрица, содержащая только интенсивности таких переходов в $Q$, а остальное в ней равно нулю. Тогда

$$
\lambda_{\mathrm{out},1}=\boldsymbol\pi H_1\mathbf e,
\qquad
\boldsymbol\alpha_1=\frac{\boldsymbol\pi H_1}{\lambda_{\mathrm{out},1}},
$$

где $\boldsymbol\alpha_1$ — распределение состояния **сразу после** типичного выхода первого узла.

Чтобы получить интервал $\Delta$ до следующего выхода, считаем все выходы первого узла поглощением. Субгенератор до такого выхода равен $T_1=Q-H_1$, следовательно,

$$
\boxed{F_\Delta(t)=1-\boldsymbol\alpha_1e^{(Q-H_1)t}\mathbf e,\quad t\ge0.}
$$

Средний интервал равен

$$
\boxed{\mathbb E[\Delta]=\frac1{\lambda_{\mathrm{out},1}}.}
$$

Это позволяет проверить, насколько выходной поток отличается от пуассоновского, и далее рассчитывать корреляции соседних интервалов через матрицы отмеченных переходов.

## 11. Один численный пример: расчёт и проверка

Зададим двухсостояний MAP (здесь частный случай MMPP):

$$
D_0=\begin{pmatrix}-0.8&0.35\\0.55&-2.85\end{pmatrix},\qquad
D_1=\begin{pmatrix}0.45&0\\0&2.30\end{pmatrix},
$$

$$
K_1=K_2=R=2,\qquad\mu_1=1.8,\quad\mu_2=1.35,\quad\nu=0.9.
$$

Основная цепь имеет $m(K_1+1)(K_2+1)(R+1)=2\cdot3^3=54$ состояния. Для расчёта условной задержки построена дополнительная помеченная цепь со 144 переходными состояниями.

|---|---:|
| Интенсивность внешних поступлений $\lambda$ | 1.169444 |
| Интенсивность успешных выходов узла 2 | 0.805155 |
| Интенсивность потерь при внешнем приходе | 0.246505 |
| Интенсивность потерь после узла 1 | 0.117784 |
| **Вероятность окончательной потери** | **0.311506** |

| Среднее время до любого исхода $L/\lambda$ | 2.258439 |

```bash
python -m pip install numpy scipy
python map_tandem_orbit_example.py
```

**Полный код расчёта генератора, стационарного распределения, потерь, помеченной цепи и распределения межвыходных интервалов:**


```python
#!/usr/bin/env python3
"""Точный расчёт MAP/M/1/K1 -> M/1/K2 с общей конечной орбитой."""
import numpy as np
from scipy.linalg import expm, solve

# Единственный численный пример. Вместимость узлов включает прибор.
D0 = np.array([[-0.80, 0.35], [0.55, -2.85]], dtype=float)
D1 = np.array([[0.45, 0.0], [0.0, 2.30]], dtype=float)
K1, K2, R = 2, 2, 2
mu1, mu2, nu = 1.80, 1.35, 0.90
m = D0.shape[0]


def invariant(G):
    """Строка стационарных вероятностей конечной неприводимой цепи."""
    n = G.shape[0]
    M = G.T.copy()
    M[-1, :] = 1.0
    b = np.zeros(n)
    b[-1] = 1.0
    p = solve(M, b)
    assert np.max(np.abs(p @ G)) < 1e-9
    return p


# 1. Генератор Q = D0 ⊗ I + D1 ⊗ PA + I ⊗ B.
zstates = [(a, b, r) for a in range(K1 + 1)
           for b in range(K2 + 1) for r in range(R + 1)]
zidx = {z: i for i, z in enumerate(zstates)}
N = len(zstates)
PA = np.zeros((N, N))
B = np.zeros((N, N))
H1 = np.zeros((m * N, m * N))
H2 = np.zeros_like(H1)
loss0 = np.zeros(m * N)
loss12 = np.zeros(m * N)


def add_B(z, target, rate):
    i, j = zidx[z], zidx[target]
    if i != j:
        B[i, j] += rate
        B[i, i] -= rate


for z in zstates:
    a, b, r = z
    if a < K1:
        target = (a + 1, b, r)
    elif r < R:
        target = (a, b, r + 1)
    else:
        target = z  # внешний отказ, численности не меняются
    PA[zidx[z], zidx[target]] = 1.0

    if a > 0:
        if b < K2:
            dst = (a - 1, b + 1, r)
        elif r < R:
            dst = (a - 1, b, r + 1)
        else:
            dst = (a - 1, b, r)
        add_B(z, dst, mu1)
        for v in range(m):
            H1[v * N + zidx[z], v * N + zidx[dst]] = mu1
    if b > 0:
        dst = (a, b - 1, r)
        add_B(z, dst, mu2)
        for v in range(m):
            H2[v * N + zidx[z], v * N + zidx[dst]] = mu2
    if r > 0 and a < K1:
        add_B(z, (a + 1, b, r - 1), r * nu)

Q = np.kron(D0, np.eye(N)) + np.kron(D1, PA) + np.kron(np.eye(m), B)
assert np.max(np.abs(Q.sum(axis=1))) < 1e-11
assert np.min(Q - np.diag(np.diag(Q))) >= -1e-12
states = [(v, a, b, r) for v in range(m) for a, b, r in zstates]
index = {s: i for i, s in enumerate(states)}
for i, (v, a, b, r) in enumerate(states):
    if a == K1 and r == R:
        loss0[i] = D1[v, :].sum()
    if a > 0 and b == K2 and r == R:
        loss12[i] = mu1

pi = invariant(Q)
theta = invariant(D0 + D1)
lam = float(theta @ D1 @ np.ones(m))
lambda1 = float(pi @ H1 @ np.ones(m * N))
lambda2 = float(pi @ H2 @ np.ones(m * N))
lambda_loss0 = float(pi @ loss0)
lambda_loss12 = float(pi @ loss12)
p_loss = (lambda_loss0 + lambda_loss12) / lam
L = float(sum(pi[i] * (a + b + r) for i, (_, a, b, r) in enumerate(states)))
assert abs(lam - lambda2 - lambda_loss0 - lambda_loss12) < 1e-9
assert abs(p_loss - (1 - lambda2 / lam)) < 1e-9

# 2. Помеченная заявка: side = 1, 2 или 3 (орбита), pos = 1,2,... или 0.
tagged = []
for v, a, b, r in states:
    tagged.extend((v, a, b, r, 1, pos) for pos in range(1, a + 1))
    tagged.extend((v, a, b, r, 2, pos) for pos in range(1, b + 1))
    if r > 0:
        tagged.append((v, a, b, r, 3, 0))
tidx = {s: i for i, s in enumerate(tagged)}
nt = len(tagged)
A = np.zeros((nt, nt))
g = np.zeros(nt)  # интенсивности успешного поглощения
ell = np.zeros(nt)  # интенсивности потери помеченной заявки


def jump(i, state, rate):
    j = tidx[state]
    if i != j and rate > 0:
        A[i, j] += rate


for i, (v, a, b, r, side, pos) in enumerate(tagged):
    for w in range(m):
        if w != v and D0[v, w] > 0:
            jump(i, (w, a, b, r, side, pos), D0[v, w])
        rate = D1[v, w]
        if rate == 0:
            continue
        if a < K1:
            target = (w, a + 1, b, r, side, pos)
        elif r < R:
            target = (w, a, b, r + 1, side, pos)
        else:
            target = (w, a, b, r, side, pos)
        jump(i, target, rate)

    if a > 0:
        if side == 1 and pos == 1:  # завершение помеченной на узле 1
            if b < K2:
                dst = (v, a - 1, b + 1, r, 2, b + 1)
            elif r < R:
                dst = (v, a - 1, b, r + 1, 3, 0)
            else:
                dst = None
                ell[i] += mu1
        else:  # завершение чужой заявки на узле 1
            newpos = pos - int(side == 1)
            if b < K2:
                dst = (v, a - 1, b + 1, r, side, newpos)
            elif r < R:
                dst = (v, a - 1, b, r + 1, side, newpos)
            else:
                dst = (v, a - 1, b, r, side, newpos)
        if dst is not None:
            jump(i, dst, mu1)

    if b > 0:
        if side == 2 and pos == 1:
            g[i] += mu2  # успешное завершение помеченной заявки
        else:
            jump(i, (v, a, b - 1, r, side, pos - int(side == 2)), mu2)

    if r > 0 and a < K1:
        if side == 3:
            jump(i, (v, a + 1, b, r - 1, 1, a + 1), nu)
            if r > 1:
                jump(i, (v, a + 1, b, r - 1, 3, 0), (r - 1) * nu)
        else:
            jump(i, (v, a + 1, b, r - 1, side, pos), r * nu)

for i in range(nt):
    A[i, i] = -A[i, :].sum() - g[i] - ell[i]
assert np.max(np.abs(A.sum(axis=1) + g + ell)) < 1e-11

# Начальный вес — на одно внешнее поступление (не на принятую заявку).
gamma = np.zeros(nt)
for i, (v, a, b, r) in enumerate(states):
    for w in range(m):
        weight = pi[i] * D1[v, w] / lam
        if a < K1:
            target = (w, a + 1, b, r, 1, a + 1)
        elif r < R:
            target = (w, a, b, r + 1, 3, 0)
        else:
            continue  # немедленная потеря, T = 0
        gamma[tidx[target]] += weight

h = solve(-A, g)              # h_i = P(успех | состояние i)
weighted_time = solve(-A, h)  # E[T 1_успех | состояние i]
p_success = float(gamma @ h)
mean_success = float((gamma @ weighted_time) / p_success)
mean_all = float(gamma @ solve(-A, np.ones(nt)))
assert abs(p_success - lambda2 / lam) < 1e-9
assert abs(mean_all - L / lam) < 1e-9

# 3. Выход первого узла: распределение и корреляция интервалов.
alpha = pi @ H1 / lambda1
Z = H1 - Q
u1 = solve(Z, np.ones(m * N))
mean_delta = float(alpha @ u1)
second_delta = float(2 * alpha @ solve(Z, u1))
cross_delta = float(alpha @ solve(Z, solve(Z, H1 @ u1)))
```
