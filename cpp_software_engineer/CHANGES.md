# Исправления кода

В новых исходниках каждый смысловой добавленный или изменённый блок отмечен ASCII-комментарием `Manual correction of AI-generated code`.

- **02.02:** исправлена классификация уравнения. Только точно нулевой старший коэффициент переводит его в линейное. Входные коэффициенты остаются `double`; промежуточные расчёты и корни имеют тип `long double`. Статические проверки требуют расширенного диапазона этого типа, доступного, например, в GCC на x86-64 Linux. На платформе, где `long double` совпадает с `double`, программа намеренно не собирается вместо выдачи ненадёжных результатов на крайних входных данных. Нормализация, терявшая корни `x² - 10¹³ = 0`, удалена. Дискриминант сравнивается с нулём с относительным допуском `1e-12` относительно `|b²| + |4ac|`. При попадании в допуск вывод явно сообщает о приближённой классификации как двойного корня. Это не утверждение о точной кратности корня исходного уравнения. Формула через `q` уменьшает потерю точности при вычислении двух различных корней.
- **02.05:** допустимый порог явно ограничен: `epsilon > 4 / 20000001` (примерно `1.9999999e-7`). Более строгий запрос отвергается сразу, без длительного цикла. Для допустимого порога ряд Лейбница требует не более 10 миллионов слагаемых. Используется компенсированное суммирование. Для ряда Маклорена проверяется не только очередной член, но и оценка всего остатка; это более строгий критерий остановки. Вывод правильно называет оценки границами ошибки усечения. Они относятся к точной арифметике и не включают ошибку округления `double`.
- **02.06, 02.07:** компенсированное суммирование Ноймайера сохраняет малый остаток при взаимном сокращении больших чисел. Для `-1e100, 1, 1e100` среднее получается `1/3`, а не ноль. Стандартное отклонение считается с делением на `N`, как характеристика заданной коллекции, а не несмещённая оценка дисперсии генеральной совокупности. В 02.07 добавлены регрессионный тест и подсказка ввода до EOF.
- **02.08:** изменена подпись результата: длина — число элементов, включая начальное число и конечную единицу. Максимум: 119 элементов для начала 97; переходов при этом 118.
- **02.09:** расширены тесты существующей обработки недопустимых аргументов и нулевых аргументов НОД. Это расширение покрытия, а не новый алгоритм НОД/НОК.
- **03.02, 03.06:** расширены тесты аргументов конструкторов. В 03.06 создание демонстрационной коллекции вынесено в `make_shapes()`; полиморфизм работал и до этой правки.
